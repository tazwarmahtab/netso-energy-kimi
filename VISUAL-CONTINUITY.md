# Netso Visual Continuity Map

## Purpose

The homepage is treated as one continuous visual narrative. Every visual asset has an explicit semantic role and evidence state. A section may introduce a visual, transform it, abstract it, or provide evidence about it. It should not introduce an unrelated visual merely for decoration.

**daylight generation -> dusk occupation/lighting**

They should remain labelled as a **reference configuration**, not a commissioned project.

### Secondary visual assets

- `solar-roof-dusk.jpg` is an underside architectural canopy view at dusk. It supports a physical-asset story, not a financial-performance claim.
- `neighborhood-aerial.jpg` is a broad industrial/city rooftop view with existing solar arrays. It supports the distributed-network thesis but should not be presented as Netso-owned operating portfolio evidence.

## Transition rules

1. Dark cinematic stages use the canonical `forest-dark` surface. Near-identical custom greens should not create hard seams.
2. Dark-to-dark transitions use a short gradient bridge rather than a new visual block.
3. Dark-to-light transitions use a deliberate tonal ramp. They are narrative transitions, not arbitrary palette changes.
4. Reused visual worlds should preserve spatial identity where possible. The strongest continuity pattern is the same roof becoming a technical model, economic abstraction, or operational view.
5. Reference, illustrative, project-specific and live states must be visually distinguishable.
6. A visual asset cannot prove a number that the asset itself does not contain evidence for. Numbers need an appropriate label, methodology or project evidence.
7. A section transition should preserve at least two of three anchors: **subject, lighting, geometry**. A transition that preserves none of them is a hard cut and should be intentional.

## Current homepage sequence

**Hero -> metadata rail -> reference architecture -> illustrative economics -> reference operations -> RMG technical considerations -> reference engineering model -> customer outcomes -> process -> macro rationale -> network -> origination**

The objective is that every step feels like a change in representation of the same Netso thesis, not a collection of unrelated landing-page modules.
